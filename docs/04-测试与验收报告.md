## 4. 浏览器操作覆盖

1. 创建正式局，确认工作重点，进入两步教学并实际运行工作。
2. 暂停后等待、刷新页面、继续正式存档，确认游戏毫秒不变。
3. 打开评估目标并返回工位。
4. 演示手机被抓，确认caughtCount为1。
5. 日末进入评估，显示熟练晋升，再进入第4天。
6. 展示结局与演示标记，确认正式历史记录未增加。
7. 多种视口均无文档横向溢出，暂停弹窗尺寸不超过视口。

自动断言分为9组（响应式4组）。小屏与横屏允许纵向滚动，不以强制缩小文字换取全屏无滚动。截图是浏览器渲染，不能等同于手机真实安全区、软键盘和系统字体环境。

## 7. 复测方法

规则回归：`npm test`。语法检查：`npm run check`。静态构建：`npm run build`。

浏览器回归：先运行`npm start`，再在独立终端运行`node scripts/browser-smoke.mjs`。需要安装或提供外置Playwright；可通过环境变量`PLAYWRIGHT_MODULE`指定其index.mjs路径，`BROWSER_CHANNEL`默认msedge，`GAME_URL`默认localhost:4173。

浏览器脚本使用隔离的无头浏览器上下文，不读取用户的真实浏览器档案。执行结果重新写到artifacts目录；截图需要人工看过才能更新“人工检查完成”结论。

修改规则后先跑相关用例，再跑全部33项；修改UI后运行浏览器脚本并查看受影响截图。没有新修改或新风险时不反复扩大测试范围。
