# 项目解读：今天摸鱼了吗？

当前版本 v0.2.6，规则 0.5-r1。“小红书工具”仓库当前承载一个职场题材离线 H5 游戏。

## 产品定位

通过十个工作日的选择，在能力成长、老板评价、交付压力和个人快乐之间寻找平衡。工作带来技能和交付；休息帮助恢复精力和快乐。结局既展示职场成绩，也给低快乐玩家理解与鼓励。

## 一局游戏的循环

选择当天工作重点 → 工作或休息 → 应对巡视与突发事件 → 60 秒有效时间结束 → 任务验收与结转 → 必要时职级评估 → 下一工作日。第十天后进入称号、快乐评价和本机留言。连续低好感评估也可能提前结束一局。

教学、事件选择、手动暂停和切后台会阻止有效游戏时间继续推进。事件只能选择生效一次，结算确认不能重复领奖。

## 属性之间的关系

| 属性 | 作用 |
| --- | --- |
| 精力 | 工作消耗的资源；低于 30 时效率减半，归零无产出，持续疲劳可能返工 |
| 技能 | 工作积累经验，每 40 点提升一级，上限 10 级，参与晋升判断 |
| 老板好感 | 巡视认可、被抓及交付奖惩影响它，决定晋升资格和降级风险 |
| 快乐 | 摸鱼、休息等行为带来变化，参与平衡加成和最终评价 |

精力至少 50、快乐至少 40 时，工作有 1.15 倍协同加成；两者都至少 70 时为 1.25 倍。精力与快乐需要主动安排，不能只看交付进度。

## 任务结转

当天目标 = 所选重点基础目标 + 职级修正 + 前日结转 + 当日接取的追加目标。

未完成量 = max(0，当天目标 − 最终进度)。下一日只增加未完成量，不把整项任务再加一次，也不会继承已经结算的事件奖励。切换工作重点不清空结转，超额完成不预支未来任务。最终日只记录未完成量，不创造第十一天。

例如第一天目标 24、完成 20，则结转 4；次日选基础目标 14 的学习任务，初级员工的目标为 18。若只完成 10，再结转 8。结转可能持续增加压力，后续平衡应重点观察后半程目标和快乐曲线。

## 代码架构

| 文件 / 目录 | 职责 |
| --- | --- |
| src/config.js | 动作、事件、称号及规则版本 |
| src/engine.js | 不依赖 DOM 的确定性规则引擎，统一计算属性和奖励 |
| src/storage.js | 本机存档、校验和、版本检查和个人记录 |
| src/app.js | 界面、输入、状态切换与生命周期 |
| src/music.js | Web Audio 音乐合成和启停 |
| src/style.css | 横屏布局、旋转适配与弹窗 |
| assets/ | 游戏使用的十五张压缩图片 |
| design-source/02_art/ | 对应的美术原件 |
| promo-v0.2.6/ | 三张宣发插画 |
| scripts/ | 本地服务、素材处理、离线构建 |
| tests/ | 规则行为测试 |
| release/ | 当前 v0.2.6 静态 H5 交付包 |

没有使用游戏引擎或前端框架。逻辑以 100ms 固定步长推进，画面刷新不直接决定奖励。随机状态随局保存，日末结算保存独立凭据，避免重复领奖或重复结转。

存档包含校验和与规则版本，旧版本不自动迁移。校验和用于发现损坏，不提供服务器级防作弊。演示局不会污染正式局及个人记录。

## 音乐、美术与横屏

背景音乐通过振荡器按短时间窗口调度音符，不需要音频文件。首次用户手势后启动，默认开启，可通过声音开关关闭，切后台停止。真实播放仍受浏览器音频策略限制。

十五张 JPEG 覆盖工作、摸鱼、巡视和六种事件。事件弹窗采用插画、情境与真实可点击选择；休息期间保留对应场景。美术原件保留用于重新压缩。

竖屏容器中游戏与顶层弹窗各自旋转，不会改变宿主 App 导航栏或系统键盘方向。宣发图属于插画，不能冒充实机截图。

## 本地运行与检查

Node.js 20+ 下执行 `npm start`，访问 http://localhost:4173/。首次构建先执行 `npm ci`，再执行 `npm test`、`npm run check`、`npm run build`。

`dist/` 输出经典脚本离线包，入口 `index.html` 位于根目录。压缩目录内容后上传，不能额外嵌套 dist 文件夹。版本 ZIP 是 H5 包，不是 Windows 或 Android 安装程序。

访问 `http://localhost:4173/?debug=1` 可打开开发演示台。`python scripts/prepare-assets.py` 可用仓库原图重新生成 JPEG，需要 Pillow。

## 当前边界与后续方向

已实现十天闭环、六类事件、三次评估、六个称号、本机留言与记录、音乐、横屏及任务结转。

尚无跨玩家留言、账号、云同步、内容审核、联网排行或自动上线。跨玩家内容需要额外后端、平台能力与内容管理设计。GitHub 公开不代表小红书审核通过，也不是公网部署。

当前 39 项规则测试覆盖结转、重复结算、巡视抓获与识破、事件成本、晋升降级、存档校验及十天闭环。真机音频、低端性能、容器适配、长期数值平衡仍需验证。

历史设计文档保留过程参考，当前行为以源码、README 和 CHANGELOG 为准。规则修改需同步版本与行为测试，界面修改需浏览器检查，不让渲染代码直接发奖励。
