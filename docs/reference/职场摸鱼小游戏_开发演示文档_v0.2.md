# 职场摸鱼小游戏开发演示文档
打工人今天摸鱼了吗
版本 0.2  游戏设计与开发沟通稿
2026年9月11日

本项目是一款以职场生活为背景的轻策略小游戏。玩家扮演新入职的打工人，在努力工作、恢复精力和应付老板巡视之间做选择，经历职级评估，最终获得职场成绩与打工幸福感两份结果。

演示版需要完成一条可重复体验的闭环：进入游戏、学习操作、完成工作日、接受职级评估、获得结局、再次挑战。技术团队可依据本文拆分状态逻辑、配置、界面信息、存档与验收任务。文案编号可作为配置键使用。

本版本保留已确定的玩法方向，将数值初稿补成可实现的规则。所有平衡参数仍需试玩验证。本文是演示版的规则基线；与策划表 v0.1 不同之处见第 2 节，旧表不随本次文档自动更新。

阅读顺序：策划与项目讨论先看 1 至 3 节；客户端与测试重点看 4 至 11、18 至 22 节；文案和内容配置重点看 12 至 17 节。文档定义接入所需行为，不预设引擎、服务器或小红书平台接口。

## 1 游戏定位与演示范围
核心体验是“再摸几秒，还是现在收手”。工作提供真实成长，巡视提供短时压力，职级评估让短期选择产生长期后果。摸鱼恢复精力并积累快乐，因此玩家有理由主动承担风险。

| 项目 | 演示版规格 |
| --- | --- |
| 游戏局长 | 10 个工作日，每日 60 秒有效时间，共 10 分钟操作时间，另加阅读和选择 |
| 评估节奏 | 第 3、6、9 天日末评估，第 10 天最终结算 |
| 操作方式 | 点选持续动作，无需长按或连续点击，随时可暂停 |
| 核心状态 | 精力、技能经验、老板好感、快乐、当日任务进度 |
| 工作选择 | 日常工作、学习进修、紧急任务，每日开工前选择一次 |
| 职级 | 初级员工、熟练员工、项目负责人 |
| 内容范围 | 三种核心动作、两种摸鱼方式、六个首版事件、六种结算称号或结局 |
| 扩展储备 | 另四个事件的完整文案和规则，默认关闭 |
| 单局之外 | 称号收集、个人最佳记录、继续未完成的一局 |

演示版不包含多人竞争、付费养成、广告复活、工位装扮、技能树、复杂同事关系和更高职级。这些功能不会成为核心闭环的前置依赖。分享只提供结算内容和发起入口，取消分享不影响奖励。

暂定验收目标是玩家能够解释工作与摸鱼的取舍，能看懂被抓和评估的原因，并愿意尝试第二种发展路线。本文中的通过标准是计划测试的目标，不代表已有测试结果。

## 2 版本修订与统一术语
本版将上一版的模糊边界改为统一判定，避免不同模块各自实现。

| 修订项 | v0.2 的统一处理 |
| --- | --- |
| 真实工作 | 只有精力大于零、实际产生进度的工作时长计入巡视认可 |
| 收手过程 | 不涨精力、不涨快乐、不涨技能、不涨进度，仍可被抓 |
| 巡视处罚 | 每次最多一笔处罚；识破后又摸鱼不重复扣分，但仍记录本次被抓 |
| 装忙识破 | 同次巡视累计 4 秒识破；切换动作不能重置累计 |
| 精力误差 | 固定以 0.1 秒为规则步长，按步初精力选效率，避免帧率改变收益 |
| 摸鱼时长 | 无老板观察、正在摸鱼且精力或快乐实际增长时才累计 |
| 事件日程 | 日初决定当日事件名额；周五需求预留到第 40 秒，不能被普通事件占用 |
| 首次保护 | 仅首局教学的首次巡视被抓扣 4 好感、不扣快乐；后续全为常规规则 |
| 末日评估 | 第 10 天不评职级，即使好感低于 25 也只影响末局成绩 |

“工作日”是一次 60 秒运行段。“巡视”包含预警与观察，但只有观察时段会检查玩家动作。“任务目标”是当日进度要求，不等于技能经验。“快乐”是局内累积属性；“幸福感”是结束时根据快乐和剩余精力计算的成绩。

“获准休息”只来自事件，既不算摸鱼也不算工作。“配置版本”固定本局参数；修改参数对新局生效，避免继续游戏时规则突然变化。“首局教学”只完成一次，重玩可主动进入练习，但练习不写正式记录。

## 3 玩家流程与现场演示脚本
完整流程为：开始页 → 日初简报 → 选择重点 → 工位操作 → 日末结算 → 必要时职级评估 → 下一工作日。第 10 天日末进入最终结算；失败则直接进入失败结算。暂停、事件选择和目标详情均覆盖在当前流程上，关闭后返回原状态。

| 演示段 | 操作与画面信息 | 需要讲清的玩法 |
| --- | --- | --- |
| 开始与任务 | 点击上班，看到今天的任务目标、奖励和精力 | 每天先选要做什么 |
| 前 8 秒 | 工作 5 秒，发呆 3 秒，属性即时变化 | 工作有收益也有消耗，摸鱼能恢复 |
| 第一次巡视 | 第 12 秒预警，第 14.5 秒开始观察 | 收手需要时间，预警提供反应机会 |
| 主动出错 | 在独立练习局中演示刷手机被抓 | 显示扣分来源，一次失误不结束游戏 |
| 日末交付 | 展示进度、达标奖励、下班恢复 | 做了多久与有没有完成任务是两件事 |
| 第 3 天评估 | 用技能 3、好感 60 的演示快照展示晋升 | 两个门槛同时达标才能升级 |
| 结局对比 | 展示晋升路线与幸福感路线的两份快照 | 升职和快乐可以分别追求 |

演示快照由开发调试入口加载，不伪装成真实游玩记录。快照和练习均标记 demo=true，结算显示“演示数据”，不更新个人最佳，也不参与后续真实分享记录。标准玩法始终可以从第 1 天完整玩到第 10 天。

讲解者可用约 5 分钟展示核心机制，再让体验者独立完成一局。演示快照只省略等待，不改变正式规则。快照需要包含状态、配置版本及随机日程，不能只改屏幕上的数字。

## 4 页面与交互规格
界面以状态和反馈为中心。本节规定必须出现的信息与行为，不限制视觉风格和引擎。

| 页面编号 | 必备信息 | 操作与转移 |
| --- | --- | --- |
| UI01 开始页 | 游戏名、继续进度、称号入口 | 开始新局；有存档时显示继续第 n 天；重开先提示覆盖 |
| UI02 日初简报 | 工作日、职级、当前属性、下次评估日 | 选择三种重点之一；展示目标和成败后果；确认开工 |
| UI03 工位 | 剩余秒数、任务进度、精力、技能级与经验、好感、快乐、当前动作 | 工作、装忙、摸鱼方式、暂停、查看评估目标 |
| UI04 事件 | 事件标题、对白、两个选项及明确代价 | 选择一次；不满足精力条件的选项禁用并写原因 |
| UI05 暂停 | 当前天数、已用时间、正在执行的动作 | 继续；返回首页并保留；重新开始提示覆盖 |
| UI06 日末 | 当日进度、技能增量、奖励与处罚明细、恢复前后精力 | 确认后进入评估或下一日；日末奖惩不随点击重复 |
| UI07 评估 | 两项门槛、当前数值、结论、下期恢复建议 | 确认；升降职规则从下一日生效 |
| UI08 结局 | 职场成绩、幸福感、摸鱼时间、被抓次数、可选称号 | 再来一局；查看记录；可选分享 |
| UI09 称号记录 | 已解锁称号、条件、个人最佳 | 返回；未解锁展示条件，不提供付费跳过 |

摸鱼不是一个会自动随机选择的按钮。玩家明确选择“发呆”或“刷手机”。点中当前动作不重新开始计时。收手期间显示剩余时长，此时动作按钮不接受第二次切换；暂停仍可用。

属性提示不能遮挡巡视倒计时。颜色只作辅助，状态必须有文字。奖励与处罚保留到日末明细。游戏切到后台立即暂停，返回后等待玩家点击继续，不在后台计算任何收益或处罚。

## 5 局内状态与属性规则
全部局内属性在新局重置，日末仅按明确规则保留或恢复。进度允许超过目标，奖励仍只结算一次。经验不因降级清零。

| 字段 | 初始值与范围 | 计算与保留规则 |
| --- | --- | --- |
| energy 精力 | 80，0 至 100 | 工作消耗、摸鱼恢复；每天结束恢复 30，上限 100 |
| skillXp 技能经验 | 0，非负 | 累积经验；技能等级 min(10, 1 + floor(skillXp / 40)) |
| favor 好感 | 50，0 至 100 | 巡视、错误、任务和事件改变；跨日保留 |
| joy 快乐 | 0，0 至 100 | 摸鱼与事件增加，被抓可减少；跨日保留 |
| taskProgress 进度 | 0，非负 | 工作增加、低精力错误减少；每天清零 |
| rank 职级 | 1 | 1 初级、2 熟练、3 负责人；只在正式评估改变 |
| warningStreak 警告 | 0，0 至 2 | 仅最低职级正式评估使用，见第 10 节 |
| idleSuccessMs | 0，非负 | 统计成功摸鱼时间；暂停、收手、获准休息不计 |

精力效率：energy≥30 时为 1；0<energy<30 时为 0.5；energy=0 时为 0。效率影响技能和进度，不影响工作精力消耗。精力为零时继续点工作不会产生进度，也不能获得巡视工作认可。

每累计 10 秒低精力工作触发一次错误，进度减 3、好感减 2。低精力包含零精力。切换动作或恢复到正常精力只暂停累计，不清零；每天日初清零。进度扣至零为止。错误不扣技能经验。

内部保留小数或等价定点数。规则比较使用内部值，不能用显示的整数判断晋升。界面精力、快乐和进度可显示一位小数；好感显示整数；计时显示到一位小数；技能经验显示整数部分并配进度。达到技能 10 级显示“技能已满级”，经验仍可保留用于记录。

## 6 动作状态机与切换
运行时的动作互斥。动作集合为 WORK、IDLE_THINK、IDLE_PHONE、PRETEND、WRAP_UP、APPROVED_REST。暂停是外层运行状态，不替换动作本身。

| 动作 | 每秒基础变化 | 切换规则 |
| --- | --- | --- |
| WORK 工作 | 经验 +1、进度 +1、精力 -1.5 | 应用工作重点倍率与精力效率；可立即转装忙或摸鱼 |
| IDLE_THINK 发呆 | 精力 +2、快乐 +0.4 | 切出前收手 0.2 秒 |
| IDLE_PHONE 手机 | 精力 +3、快乐 +0.7 | 切出前收手 1.2 秒 |
| PRETEND 装忙 | 精力 -0.2，其他不变 | 可立即转工作或摸鱼，不恢复精力 |
| WRAP_UP 收手 | 所有属性收益为零 | 保存目标动作，结束后进入目标；期间仍算可被抓状态 |
| APPROVED_REST | 由事件规定精力和快乐收益 | 持续到事件计时结束；不能切换普通动作 |

从一种摸鱼切换到另一种摸鱼，也必须完成原动作的收手时间。收手倒计时不能通过重复点击重置或缩短。工作和装忙之间切换无延迟。日初进入 WORK；事件结束后回到事件前动作，但获准休息结束统一进入 WORK。

被抓时，记录一次该巡视的 caught 标记，终止摸鱼或收手，并强制转 WORK。这里不额外收手，是失败后的恢复处理。老板在场时可以再次主动选择摸鱼，但本次不重复处罚，且无法获得成功摸鱼时长。装忙识破不强制切换，但弹出原因提示。

一个动作按钮只改变动作，不立即发放每秒收益。收益由统一游戏时钟产生，防止反复点按钮获得重复奖励。APPROVED_REST 期间选择弹窗已关闭，工作日倒计时照常运行。

## 7 工作重点与任务结算
工作重点改变成长、交付和消耗的比例。当日不能重选，但事件可以增加任务目标及附加奖惩。

| 工作重点 | 经验倍率 | 进度倍率 | 精力倍率 | 基础目标 | 达标与未达标好感 |
| --- | --- | --- | --- | --- | --- |
| 日常工作 | 1.0 | 1.0 | 1.0 | 24 | +3 或 -4 |
| 学习进修 | 1.4 | 0.6 | 1.0 | 14 | +1 或 -2 |
| 紧急任务 | 0.8 | 1.2 | 1.3 | 28 | +7 或 -6 |

目标值 = 重点基础目标 + 职级加量 + 已接受事件加量。初级加量 0，熟练加量 3，负责人加量 6。任务开始后显示最终目标，事件增量发生时显示“任务目标 24 → 30”。

每个有效时间段 dt 的工作收益为：经验增量 = dt×经验倍率×精力效率；进度增量 = dt×进度倍率×精力效率；精力消耗 = dt×1.5×精力倍率。每 0.1 秒按步初精力选定效率，完成本步后截断精力下限；输入时间也量化到下一步边界，所有设备使用同一规则。

完成目标时提示“今日目标已达到”，不提前发好感。玩家仍可以工作成长或摸鱼。后续事件加量、低精力错误可能让进度再次低于目标，最终一律在日末判断 taskProgress≥taskTarget。

基础任务与已接受事件统一使用最终达标结果。将本次所有日末好感增量相加，再一次限制在 0 至 100，写入结算凭据。例：日常任务叠加临时加活，完成最终目标获得 +3+5=+8；未完成获得 -4-3=-7。不能按不同顺序逐次截断上限而产生不同结果。

## 8 老板巡视与预警日程
普通模式每天基础巡视次数由职级决定。每次真实巡视必有完整预警，不能用完全无预警的出现制造难度。

| 职级 | 基础次数 | 单次观察时长 | 日程生成参考锚点 |
| --- | --- | --- | --- |
| 初级 | 3 | 5 秒 | 14.5、31、47 秒 |
| 熟练 | 2 | 6 秒 | 20、43 秒 |
| 负责人 | 1 | 7 秒 | 30 秒 |

在每个锚点加入 -2 至 +2 秒的随机偏移，按 0.1 秒量化。巡视观察不重叠，真实预警通常提前 2.5 秒；持有提醒券时下一次真实预警提前 4 秒并消耗券。任何预警不得早于第 8 秒，观察结束不得晚于第 60 秒。候选不合法时重新取偏移，最多尝试 20 次，仍失败则使用未偏移锚点。

每天 20% 概率生成一次假脚步信号，没有观察和奖惩。假信号也持续 2.5 秒；从不与真实预警或观察重叠，并与其他预警开始时间至少相隔 8 秒。无法放入时省略。信号初始文案相同，不提前暴露真假。

每次基础巡视离开时，以 20% 概率尝试一次折返。离开 3 秒后发预警，再按 2.5 秒或提醒券的 4 秒等待后观察。折返观察时长与该日基础巡视相同。每天最多安排一次折返，折返不能再次折返。与基础巡视、预警间距、假信号或日末冲突时放弃本次尝试，不修改已公布的预警。

教学首日固定首次观察为第 14.5 秒，不加入偏移；该日假信号和折返关闭，其余两次观察固定为第 31、47 秒。真实日程在开工时生成并保存，折返随机结果在离开时生成后立即保存，继续存档不得重抽。

## 9 巡视判定和同刻处理
每次巡视维护 workMs、pretendMs、caught、exposed、penaltyApplied 与 settled。所有累计只发生在观察时段，预警时不累计。

| 条件 | 处理 |
| --- | --- |
| 处于摸鱼或收手 | caught 置真；本巡视首次被抓累计次数 +1；若未处罚则好感 -12、快乐 -5；强制进入工作 |
| 累计装忙达到 4 秒 | exposed 置真；若未处罚则好感 -5；不强制切换 |
| 观察结束且没有被抓或识破，工作累计至少 3 秒 | 好感 +4 |
| 无违规且工作不足 3 秒，装忙累计至少 1 秒且少于 4 秒 | 好感 +1 |
| 其他情况 | 无巡视奖励 |

同一巡视最多一笔违规处罚，以先触发为准。识破后又摸鱼，仍记录 caught，但不再扣好感和快乐；奖励始终取消。被抓次数按巡视而不是点击次数累计。教学首次巡视仅替换被抓的扣分数值，不改变状态恢复。

统一时序：先计算上一段时间内的动作收益和累计，随后处理到期状态；结束的巡视先结算，收手完成和获准休息完成再切换；然后处理当前时刻的玩家动作输入；再开始新巡视并检查当前动作，已经开始的巡视也在每次动作输入后立即检查；最后处理事件弹窗和显示提示。巡视在观察开始时立即检查，因此摸鱼不能在开始后白赚一个步长。

观察区间采用开始包含、结束不包含。收手恰好完成于巡视开始时视为已收好。装忙恰好累计到 4 秒并同时遇到巡视结束，先触发识破。奖励与处罚同刻发生时，先确定唯一分支再写入增量。

第 60 秒优先完成截至该时刻的收益、错误与巡视结束结算，然后进行日末任务结算、评估或最终结局，停止接受普通动作和新的事件。只有时间区间确实跨过一个收益段时才增加数值，UI 刷新不产生收益。

## 10 职级评估与失败恢复
评估只在第 3、6、9 天发生，使用当日日末任务和事件奖惩结算后的技能及好感。精力不直接参与晋升，但影响此前的产出。

| 当前职级 | 晋升条件 | 好感低于 25 | 其他情况 |
| --- | --- | --- | --- |
| 初级员工 | 技能≥3 且好感≥60 | 连续警告次数 +1，达到 2 次时失败 | 未满足晋升则维持；好感≥25 时清除警告 |
| 熟练员工 | 技能≥5 且好感≥75 | 降至初级，警告清零 | 不满足晋升则维持 |
| 项目负责人 | 已为最高职级 | 降至熟练，警告清零 | 技能≥5 且好感≥75 为优秀，否则维持 |

先处理低好感风险，再处理晋升，最后维持。一次最多变动一级，不能跨级。升降职不改变技能、精力或好感，仅改变下一天的巡视和任务规则。第 9 天失败时不再开始第 10 天；正常完成第 10 天时不增加第四次评估。

例一：第 3 天初级技能 3、好感 60，晋升熟练。例二：技能 2、好感 100，只维持，提示缺少 1 级技能。例三：第 3 天初级好感 24 得到警告，第 6 天恢复到 25，则警告清零。例四：第 6 天从熟练降到初级，第 9 天仍低于 25，只收到第一次最低职级警告。

评估界面同时展示两个门槛及实际差值。高技能低好感给出紧急重点或关键任务建议；低技能高好感给出学习建议。不能只显示“表现一般”而不给原因。

日末处理顺序固定为任务与事件结果、职级评估、保存恢复前精力、下班恢复 30、进入下一日。失败时不再发放下班恢复；最终幸福感也取恢复前精力，避免第 10 天凭空获得成绩加成。

## 11 随机事件系统
演示版开启 E01 至 E06，E07 至 E10 为已定义但关闭的扩展事件。每天最多出现一个，首局教学第 1 天无事件，任意新局第 1 天均无普通事件。

日初先判断第 4 或 7 天的 E05 关键任务资格，再判断第 5 或 10 天的 E06 周五需求并预留名额，其余从合格普通事件等概率抽取。事件不连续两天重复；没有合格项则无事件。E10 扩展启用后作为普通候选，但在日初决定且在选择重点前展示。

普通事件安排第 15 秒，若处于预警、观察或收手则延后至三者均结束。E06 安排第 40 秒，采用同样延后规则，最晚第 50 秒仍无法弹出则取消，不补其他事件。普通事件最晚第 45 秒仍无法弹出则取消。E05 日初触发，选完重点后、开工前出现。

事件选择暂停全部时钟；玩家选择后才执行效果并恢复时钟。一次性精力成本必须够付，否则选项禁用。获准休息不能提前退出，剩余工作日时长必须足够；若不足则不弹出该事件。未选择前不扣属性，双击不重复执行。

正文可以有职场调侃，但选项下面必须展示真实影响。即时结果与日末附加奖惩分别记录：即时成本在选择时生效，目标与达标奖励写入当日任务修正，不在选择时提前加好感。

事件奖励与任务奖励共用最终是否达标的结果。事件造成的合法休息不计摸鱼、不被抓，也不积累巡视认可。休息之前已有的该次巡视违规标记不会被清除。

配置：第 2 天起普通候选，弹出早于第 40 秒。事件出现前不进入休息；A 被选中后才开始。获准休息结束转工作，收益按剩余上限截断。

| END06 重新出发 | 最低职级连续两次低好感评估 | 这份工作暂时告一段落。带上经验，下一次重新安排节奏。 |

称号可同时解锁，由玩家选一个展示。幸福感 = 四舍五入(快乐×0.7 + 最终恢复前精力×0.3)。分享标题为“我在公司坚持了 {days} 天，获得{titleName}”；正文展示最终职级、幸福感、摸鱼时间和被抓次数。个人最佳仅完整正式局更新，失败仍可记录历史结果。

## 18 数据结构与配置边界
将规则状态与画面分开：画面读取状态，按钮提交意图，规则模块返回新状态与反馈事件。以下为逻辑数据协议，不绑定开发语言或存储方案。

| 数据对象 | 最低字段 | 生命周期 |
| --- | --- | --- |
| RunState | runId、configVersion、demo、day、elapsedMs、phase、rank、energy、skillXp、favor、joy、warningStreak | 新局建立，跨日保存 |
| ActionState | action、pendingAction、wrapRemainingMs、restRemainingMs、eventBuffRemainingMs | 切换、暂停与恢复时保留 |
| DayTask | focusId、baseTarget、rankExtra、modifiers、progress、lowEnergyWorkMs、settled | 日初建立，日末封账 |
| PatrolState | patrolId、startMs、endMs、kind、workMs、pretendMs、caught、exposed、penaltyApplied、settled | 每次巡视单独保存 |
| DaySchedule | basePatrols、fakeSignal、returnScheduled、eventId、eventDueMs、eventStatus、randomState | 固定本日随机结果 |
| RunStats | idleSuccessMs、caughtCount、exposedCount、maxRank、dailyResults、completedDays | 只由规则结果更新 |
| Profile | tutorialCompleted、unlockedTitles、bestCompletedRun、currentRunRef | 独立于局内属性 |
| Settlement | settlementId、day、deltaList、rankResult、beforeRestEnergy、applied | 防重复结算的凭据 |

日初清零 taskProgress、低精力计时和巡视局部累计，保留局内属性、提醒券、警告和累计成绩。提醒券字段使用 reminderToken=0/1。phase 建议枚举 MENU、DAY_SETUP、RUNNING、EVENT_CHOICE、PAUSED、DAY_RESULT、EVALUATION、RUN_RESULT。

配置分成动作速率、工作重点、职级门槛、巡视时段、事件规则、称号条件、文案字典。事件 ID 和文案键稳定，展示文本可换，不能通过文本内容判断规则。所有配置数值应有单位和合法范围。

配置版本变化不应自动修改进行中的存档。演示阶段保留旧版本配置，或明确提示玩家重新开始，禁止无提示用新参数继续计算。数据缺字段时进入可解释的恢复失败状态，不伪造成功存档。

## 19 输入事件与结算协议
按钮输入必须先检查当前 phase 是否允许；规则事件与提示文案分开。每条需要持久化的结果带唯一 eventId 或 settlementId，防止重复点击、恢复和回调造成重复发奖。

| 输入命令 | 关键参数 | 允许状态与效果 |
| --- | --- | --- |
| START_RUN | configVersion、demo | 菜单；创建唯一新局，重置局内状态 |
| CONFIRM_FOCUS | focusId | 日初；锁定重点，生成并保存日程，开工 |
| SELECT_ACTION | actionId、inputSeq | 运行；检查动作及收手限制，再切换 |
| CHOOSE_EVENT | eventId、optionId、inputSeq | 事件选择；检查当前事件与成本，只执行一次 |
| PAUSE_RUN | reason | 运行或已有弹窗；暂停并保存，不关闭未选事件 |
| RESUME_RUN | runId | 暂停；恢复原 phase，事件未选则返回事件 |
| ACK_RESULT | settlementId | 日末或评估；只推进页面，不再次改变已结算数值 |
| RESTART_RUN | overwriteConfirmed | 用户明确确认后新建，不复用旧结算 ID |

规则输出包括 STAT_CHANGED、ACTION_CHANGED、PATROL_WARNED、PATROL_CAUGHT、TASK_TARGET_CHANGED、DAY_SETTLED、RANK_EVALUATED、RUN_FINISHED。每项输出包含发生的游戏时间、原因键、前后值和关联对象 ID，供 UI 与日志使用。

一次日末结算按事务处理：检查未结算 → 计算最终目标与达标 → 汇总任务与事件好感 → 写入属性 → 必要时评估 → 写入结果和恢复前精力 → 非失败时恢复 → 标记 applied 并保存。若恢复时已 applied，只展示已有结果。页面上“下一天”不是发奖按钮。

第 10 天保存最终成绩后结束，不再创建第 11 天。分享结果读取冻结的 RunResult，不能读取已经重开的新局实时属性。正式与 demo 的个人记录写入路径分开，调试按钮不出现在普通界面。

## 20 存档与中断处理
演示版至少支持一个进行中的正式存档和独立个人记录。存档保存当前随机状态与已经安排的巡视，防止重新进入时得到更有利的日程。

| 时机或异常 | 必须行为 |
| --- | --- |
| 日初确认 | 保存重点、任务目标、日程和事件占位后开工 |
| 选择事件后 | 保存成本、目标修正、选项结果和事件已使用标志 |
| 巡视开始与处罚 | 保存巡视频次状态及已处罚标志 |
| 运行中 | 建议每 2 秒保存一次快照，正常后台切换立即保存 |
| 暂停与退到首页 | 保存完整状态；继续时不补算离线时间 |
| 后台恢复 | 显示暂停页，等玩家点击继续 |
| 强制关闭 | 恢复最近完整快照，演示版允许最多约 2 秒进度回退，不重复发奖 |
| 存档损坏 | 提示无法读取，允许新开；保留原文件用于排查，不混入部分字段 |
| 配置不匹配 | 尝试加载存档版本；不可用时提示重开，不静默升级 |
| 无网络 | 核心单局不依赖网络请求；分享等外部能力单独失败，不影响成绩 |

存档写入采用临时副本成功后替换或等价的原子提交，避免只保存了一半。页面是否暂停与动作状态分别保存；在事件弹窗中退出，恢复后仍等待同一个选项。获准休息中退出保留剩余秒数。

性能目标是计时、收益和巡视不随帧率变化。卡顿跨过关键时刻时按事件边界逐段处理；如果已发生后台或失焦暂停，不追赶暂停期间的时间。具体帧率、机型范围和平台生命周期适配由技术验证后记录，不在未测试时承诺。

## 21 开发模块与交付顺序
拆分以可验证的功能结果为单位。此处不给未经团队估算的人天和上线日期。

| 阶段 | 交付内容 | 完成判据 |
| --- | --- | --- |
| M1 规则骨架 | 新局、时钟、互斥动作、属性、重点与任务、日末结算 | 无美术条件下能完成一天并核对数值 |
| M2 风险与成长 | 巡视日程、收手、识破、假信号与折返、评估 | 能稳定复现安全、被抓、晋升和警告 |

进入开发时需由技术确认运行载体、输入适配、存储能力、前后台生命周期、平台要求和分享方式。当前文档不声称已完成小红书接入，也不规定未经验证的 API。平台接入单独作为工作项，核心演示可以先验证玩法。

调试面板至少支持固定随机种子、指定天数和属性、载入安全巡视与被抓快照、模拟日末、查看当前任务及巡视记录。手动改数值必须标记 demo，避免测试过程污染用户记录。

## 23 试玩记录与调整方法
建议先邀请 5 至 8 名喜欢轻量游戏和职场题材的体验者完成首局，再让他们自由重玩一次。首轮尽量只记录，不替玩家做决策；只有卡住或无法继续时提供帮助并记录原因。

| 观察项 | 记录口径 | 调整依据 |
| --- | --- | --- |
| 教学理解 | 首日后能否解释精力、收手和技能与好感两门槛 | 看不懂先改提示和节奏，再改数值 |
| 风险公平感 | 每次被抓时的信号、动作、剩余收手时间 | 无预警或时序不一致属于规则问题 |
| 晋升体验 | 第3、6、9天等级、好感和评估结果 | 多数人一次都无法晋升时降低目标压力或经验门槛 |
| 动作选择 | 工作、装忙、两类摸鱼的时间比例 | 若一直工作最优，检查精力惩罚；若只装忙可晋升则修规则 |
| 工作重点 | 各重点选择天数及完成率 | 至少两种重点被用于不同目标 |
| 复玩动机 | 第二局目标与第一局是否不同 | 若都只追同一称号，检查幸福感反馈与路线差异 |
| 中断与退出 | 退出的天数、原因、是否恢复成功 | 区分局长、理解问题和恢复故障 |

记录事件至少包含 runId、configVersion、demo、游戏时刻、操作类型、结果和原因键。演示阶段可以本地导出，不需要默认上传用户信息。真实接入后再按平台和产品要求确定分析方式。

每轮只优先改变一组相关参数，例如先调精力收支，再调晋升门槛。固定随机种子复测同一场景，同时保留自由随机试玩，避免只针对一个演示脚本平衡。

首次开发评审应确认：三种动作是否都有合理用途；一局是否能走完；所有扣分是否有可读原因；页面上的目标是否与规则一致；存档是否可恢复。通过功能验收后，再决定是否开启扩展事件和更长职业路线。

## 24 技术沟通问题与配置样例
以下问题用于团队评审，不阻止先实现独立规则与演示闭环。具体实现由技术团队结合运行环境选择。

| 待确认项 | 当前产品要求 | 评审应产出的结果 |
| --- | --- | --- |
| 运行载体 | 适合短局体验，支持点击和暂停 | 目标载体、接入条件与验证样机 |
| 存储 | 单局可继续，结果不重复提交 | 保存位置、容量、失败恢复策略 |
| 时间驱动 | 以有效游戏时间结算 | 主循环与边界处理方案 |
| 分享 | 自愿发起，失败不影响成绩 | 可用能力、取消与失败回调行为 |
| 配置迭代 | 新旧局规则不能混用 | 版本加载和旧存档处理方式 |
| 测试方式 | 可固定随机并加载演示快照 | 调试入口、日志导出与用例执行方案 |

配置样例为逻辑结构，字段值应与前文一致。这里只展示一个工作重点和一个事件，不要求技术采用特定文件格式。

```json
{
  "configVersion": "0.2",
  "focus": {
    "id": "daily", "xpRate": 1.0,
    "progressRate": 1.0, "energyRate": 1.5,
    "baseTarget": 24, "successFavor": 3,
    "failureFavor": -4
  },
  "event": {
    "id": "E02", "enabled": true,
    "maxPerDay": 1, "latestShowMs": 30000,
    "optionA": {"targetDelta": 6,
      "successFavorDelta": 5, "failureFavorDelta": -3},
    "optionB": {"immediateFavorDelta": -1}
  }
}
```

配置中的 latestShowMs 采用不包含上限的约束，因此 E02 必须在 30000 毫秒之前展示。为避免误解，基础动作表的倍率与样例中的最终速率不可重复相乘。可选择只保存倍率或最终速率，但运行时必须只有一种权威计算口径。
